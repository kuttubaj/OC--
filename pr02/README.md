## 1. Анализ системных вызовов Python (strace)
Команда запуска: `strace -c python3 hello.py data/01.log`

* **Общее число системных вызовов:** В среднем интерпретатор Python делает от 600 до 1000+ системных вызовов при самом базовом запуске.
* **Вызовы для чтения файла:** Непосредственно к чтению целевого файла относятся всего 3-4 вызова: `openat` (открытие файла), `fstat` (получение информации), `read` (чтение содержимого) и `close` (закрытие).
* **Накладные расходы интерпретатора:** Огромное количество остальных вызовов — это накладные расходы на запуск виртуальной машины Python. Сюда входят: `openat` и `mmap` для поиска и загрузки стандартных библиотек (`.py` и `.so` файлов), `mprotect` для настройки прав доступа к памяти, а также чтение конфигураций окружения системы.

## 2. Сравнение cat и python3
* Утилита `cat data/01.log` выполняет около 30-50 системных вызовов.
* Скрипт `python3 hello.py data/01.log` выполняет более 600 системных вызовов.
* **Вывод:** Утилита `cat` написана на C и скомпилирована в бинарный код. Она обращается к ядру напрямую, загружая лишь базовую библиотеку `libc`. Python — это тяжеловесный интерпретатор, которому перед выполнением простейшей задачи (чтения) нужно загрузить в память собственную инфраструктуру. Для простых операций с файлами нативные C-утилиты в десятки раз эффективнее скриптовых языков.

## 3. Ответы на контрольные вопросы
**1. Почему нельзя обратиться к диску напрямую из пользовательской программы?**
Ради безопасности и изоляции. ОС (ядро) выступает арбитром между программами и железом. Если бы программы могли писать на диск напрямую, они могли бы случайно или намеренно стереть системные данные, нарушить права доступа (прочитать чужие файлы) или повредить файловую систему при одновременной записи в один и тот же сектор.

**2. Что дороже — вызов функции или системный вызов, и почему?**
Системный вызов намного дороже. Обычный вызов функции происходит внутри одного адресного пространства (user mode) и сводится к простому перемещению указателя стека. Системный вызов требует **переключения контекста** (Context Switch): процессор должен сохранить текущее состояние регистров, переключиться в привилегированный режим ядра (kernel mode), проверить права, выполнить код ядра, а затем переключиться обратно в пользовательский режим, восстановив регистры.
