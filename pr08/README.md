## 1. Алгоритм Банкира
Скрипт `banker.py` успешно проверяет состояние системы.
* Набор **bank1.txt**: Состояние БЕЗОПАСНО. Найдена последовательность `P1, P3, P4, P2, P0`.
* Набор **bank2.txt**: Состояние НЕБЕЗОПАСНО (UNSAFE). Системе не хватает ресурсов для удовлетворения потребностей любого из процессов, что неизбежно приведет к Deadlock.

## 2. Детектор циклов ожидания (TrackedLock)
В скрипте `tracked_lock.py` реализована обертка над `threading.Lock`. Вместо того чтобы наглухо зависнуть при встречном захвате замков, встроенный детектор строит граф (wait-for graph) и обходит его поиском в глубину (DFS). При обнаружении цикла выбрасывается кастомное исключение: 
`Обнаружен Deadlock! Поток Thread-2 попытался захватить LockA.`

## 3. Обедающие философы
Реализовано три режима питания философов:
1. **Иерархия ресурсов (Упорядоченный захват):** Философы всегда берут сначала вилку с меньшим `id` (адресом в памяти), а затем с большим. Deadlock невозможен. Все философы стабильно едят.
2. **Ограничение мест (Семафор N-1):** За стол допускаются максимум 4 философа одновременно. Всегда останется хотя бы одна свободная вилка, чтобы кто-то мог доесть. Deadlock невозможен.
3. **Наивный:** При запуске каждый берет левую вилку, засыпает на миллисекунду и пытается взять правую. Программа наглухо зависает из-за кругового ожидания. *(Убедиться в зависании можно, запустив `philosophers.py` — выполнение остановится на шаге 3)*.

## 4. Ответы на контрольные вопросы
**1. Почему упорядочивание захвата ресурсов исключает deadlock?**
Взаимоблокировка возможна только при одновременном выполнении 4 условий (условия Коффмана). Одно из них — **«Круговое ожидание» (Circular Wait)**. Если обязать все потоки захватывать ресурсы строго по возрастанию их порядковых номеров, замкнутый цикл в графе ожидания физически не сможет образоваться. Запрос всегда идет только «вперед», ломая условие кругового ожидания.

**2. Почему алгоритм банкира редко применяется в универсальных ОС?**
Для работы алгоритма Банкира операционной системе необходимо **заранее** знать максимальное количество ресурсов (Maximum Need), которое может потребовать каждая программа. В универсальных ОС (Windows, Linux, macOS) это невозможно: пользовательские приложения выделяют память и потоки динамически, их поведение непредсказуемо. Поэтому современные ОС используют стратегию "Страусиного алгоритма" — игнорируют проблему, а в крайнем случае убивают зависший процесс (OOM Killer).
